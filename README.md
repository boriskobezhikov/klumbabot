# Klumba rental monitor

Слушает несколько Telegram-чатов с объявлениями об аренде в реальном времени,
дёшево отфильтровывает нерелевантные сообщения, прогоняет кандидатов через
Claude (проверяет цену/спальни/срок аренды по вашим критериям) и присылает
уведомление в Telegram, когда находит подходящую квартиру.

Фильтры меняются командами боту прямо из Telegram — без SSH и без перезапуска.

Оценка стоимости проверок через Claude: ~$1-3/мес при обычной активности
чата (Haiku 4.5, с regex-предфильтром перед API).

## Как это устроено

Один аккаунт не может и читать чужую группу, и писать вам от лица бота, поэтому
тут два разных «аккаунта»:

1. **Userbot** (Telethon) — логинится под вашим личным Telegram-аккаунтом
   (вы же уже состоите в нужных чатах) и молча слушает новые сообщения. Обычный
   bot API для этого не годится — ботов нельзя добавить в чужую публичную
   группу без прав администратора.
2. **Notify-бот** (обычный Telegram-бот через BotFather) — шлёт вам находки в
   личку и принимает команды управления. Ему не нужно быть в отслеживаемых чатах.

Файлы:

| Файл | Что внутри |
|---|---|
| `main.py` | Мониторинг: приём сообщений, предфильтр, дедуп, вызов Claude, уведомления |
| `config.py` | Схема и чтение/запись `config.json`, сборка промпта |
| `chats.py` | Резолв чатов по `@username`/id, построение ссылок на сообщения |
| `commands.py` | Команды бота |

## Установка (на вашем VPS)

Нужен Debian/Ubuntu и Python 3.10+. Три шага.

**1. Склонировать и установить**

```bash
git clone git@github.com:boriskobezhikov/klumbabot.git /opt/klumba-bot
bash /opt/klumba-bot/deploy/install.sh
```

`install.sh` ставит пакеты, заводит системного пользователя `klumba`, собирает
venv, раскладывает права, регистрирует сервис в автозапуске и печатает, что
делать дальше. Запускать можно сколько угодно раз — существующие `.env`,
venv и сессию он не трогает.

**2. Заполнить настройки**

```bash
nano /opt/klumba-bot/.env
```

Откуда брать значения — в следующем разделе.

**3. Войти в Telegram и запустить**

```bash
bash /opt/klumba-bot/deploy/login.sh
systemctl start klumba-bot
```

Вход разовый: Telethon спросит номер телефона и код (код приходит в само
приложение Telegram, не по SMS). Когда в логе появится «Запущен. Слушаю: …» —
вход прошёл, нажмите Ctrl+C и стартуйте сервис.

### Откуда взять значения для .env

- **TG_API_ID / TG_API_HASH** — https://my.telegram.org → «API development
  tools» → создайте приложение (любое название). Это привязано к вашему
  личному номеру телефона, только для вас.
- **NOTIFY_BOT_TOKEN** — в Telegram напишите @BotFather, `/newbot`, следуйте
  инструкциям, получите токен вида `123456:AAExxxx`.
- **NOTIFY_CHAT_ID** — напишите что угодно своему новому боту, затем откройте
  в браузере `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` и найдите
  `"chat":{"id": ...}` — это число и есть ваш chat id. Только с этого аккаунта
  бот принимает команды.
- **ANTHROPIC_API_KEY** — https://platform.claude.com, раздел API keys,
  привяжите карту (иначе ключ не будет работать).

### Эксплуатация

```bash
systemctl status klumba-bot          # запущен ли
journalctl -u klumba-bot -f          # логи в реальном времени
systemctl restart klumba-bot         # перезапустить
bash /opt/klumba-bot/deploy/update.sh # обновить код из git и перезапустить
```

`update.sh` делает `git pull`, доставляет зависимости, обновляет юнит,
перезапускает сервис и проверяет, что тот действительно поднялся — если нет,
сразу показывает логи и возвращает ненулевой код.

Сервис поднимается сам после перезагрузки VPS и перезапускается при падении
(`Restart=always`, пауза 10 секунд).

### Как это устроено на сервере

- Процесс работает под системным пользователем `klumba` без shell — не под
  root. Он держит вашу Telegram-сессию и ключ Claude, так что лишние права ему
  ни к чему.
- Код принадлежит root и пользователю недоступен на запись; писать он может
  только в сам каталог `/opt/klumba-bot` — туда ложатся `config.json` и файлы
  сессии.
- `.env` — режим `640`, root:klumba: посторонние пользователи на машине его не
  прочитают.
- Юнит ограничен systemd-песочницей (`ProtectSystem=strict`, `ProtectHome`,
  `NoNewPrivileges`, `PrivateTmp` и т.п.) — из всей файловой системы на запись
  доступен только `/opt/klumba-bot`.

**Никому не отправляйте `.session` файлы** — они равносильны доступу к вашему
Telegram-аккаунту. В git они не попадают (`.gitignore`), права на них `600`.

## Управление из Telegram

Напишите эти команды своему notify-боту в личку. Всё применяется сразу, без
перезапуска, и сохраняется в `config.json`.

| Команда | Что делает |
|---|---|
| `/status` | Бюджет, курс, чаты, состояние предфильтра, вызовов Claude за сутки |
| `/budget 850` | Максимальная итоговая цена в месяц, $ |
| `/rate 2.7` | Курс GEL за 1 USD (для пересчёта коммуналки) |
| `/chats` | Список отслеживаемых чатов |
| `/chats add @username` | Добавить публичный чат |
| `/chats add -1001234567890` | Добавить приватный чат по id |
| `/chats rm @username` | Убрать чат |
| `/criteria` | Показать текущие критерии поиска |
| `/criteria <текст>` | Заменить их (обычный текст, его читает Claude) |
| `/prefilter` | Показать regex-предфильтр |
| `/prefilter on` / `off` | Включить/выключить предфильтр |
| `/prefilter listing <regex>` | Заменить одну из трёх регулярок |
| `/help` | Шпаргалка |

Команды принимает **только** аккаунт с `NOTIFY_CHAT_ID` — остальным бот не
отвечает вовсе.

### Какие чаты можно добавлять

Ваш личный аккаунт должен состоять в чате — бот читает их от вашего лица.

- **Публичные** — по `@username` или ссылке `https://t.me/username`.
- **Приватные** — по числовому id вида `-1001234567890`. Узнать его проще
  всего так: перешлите любое сообщение из чата боту @userinfobot, либо
  откройте чат в Telegram Web и возьмите число из адресной строки
  (`#-1001234567890`).

Для приватных чатов ссылки в уведомлениях строятся как `t.me/c/...` — они
откроются только у участников чата. У старых обычных групп (id без префикса
`-100`) ссылок на сообщения не существует, уведомление придёт без неё.

### Критерии и предфильтр

Работают в два этапа:

1. **Предфильтр** — три регулярки, отсекающие явный мусор до обращения к API:
   `listing` (признак сдачи), `bedroom` (тип жилья), `seeking` (признак поиска,
   а не сдачи). Сообщение проходит дальше, если совпало с `listing` и `bedroom`
   и при этом не выглядит как `seeking`.
2. **Claude** — читает текст объявления и сверяет с `/criteria` и `/budget`.

Тонкие настройки («только Ваке и Сабуртало», «от 40 м²», «можно с животными»)
пишите обычным текстом в `/criteria` — Claude поймёт любые формулировки.
Предфильтр трогайте, только если чат не на русском.

⚠️ **`/prefilter off` заметно увеличивает расходы.** Оценка $1-3/мес верна
именно потому, что регулярки отсекают подавляющее большинство сообщений до
вызова API. Без предфильтра в Claude уходит каждое сообщение из каждого чата.
Следите за строкой «Вызовов Claude за 24ч» в `/status`.

⚠️ **Регулярки по умолчанию заточены под русский** (`сдаю`, `в аренду`,
`спальня`). В чате на грузинском или английском они отсекут вообще всё, и
мониторинг будет молча простаивать — под такой чат их нужно расширить,
например `/prefilter listing сда(ю|ётся|ется|м)\b|в\s*аренду|for rent|rent out`.

### config.json

Создаётся автоматически при первом запуске из значений `.env`
(`TG_GROUP`, `BUDGET_USD`, `GEL_PER_USD`), после чего становится единственным
источником правды — эти три переменные из `.env` больше не читаются.

Править файл руками можно (бот подхватит при следующем старте), но обычно
проще командами. Путь можно переопределить переменной `KLUMBA_CONFIG`.

## Ограничения

- Ловит только НОВЫЕ сообщения, появившиеся пока бот запущен (это
  устроено через live-подписку на события, а не через опрос раз в час —
  так что задержка между постом и уведомлением обычно секунды).
- Пока бот выключен (упал VPS, перезагрузка без автозапуска и т.п.) —
  пропущенные за это время объявления не восстанавливаются.
- Одинаковый текст, запощенный в несколько отслеживаемых чатов, присылается
  один раз (дедуп по тексту, окно 24 часа). Дедуп живёт в памяти процесса и
  сбрасывается при перезапуске.
- Claude может иногда ошибаться в классификации (как и любой человек,
  бегло читающий объявление) — это фильтр для экономии времени, а не
  гарантия не пропустить вообще ничего.
