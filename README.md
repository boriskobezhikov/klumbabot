# Klumba rental monitor

Следит за объявлениями об аренде в Тбилиси из двух источников — Telegram-чатов
и сайта ss.ge — и присылает каждому подписчику то, что подходит под его
фильтры. Фильтры настраиваются кнопками в чате с ботом: спальни, комнаты,
бюджет, районы, источники. Регулярки бот собирает сам.

## Как это устроено

Один аккаунт не может и читать чужую группу, и писать от лица бота, поэтому
тут два «аккаунта»:

1. **Userbot** (Telethon) — логинится под вашим личным Telegram-аккаунтом и
   молча слушает чаты, в которых вы состоите. Обычный bot API для этого не
   годится: ботов нельзя добавить в чужую публичную группу.
2. **Бот** (через BotFather) — общается с людьми, показывает меню и рассылает
   находки. В отслеживаемых чатах ему быть не нужно.

### Один разбор на всех

Claude вызывается **один раз на объявление** и только извлекает факты: цена,
спальни, комнаты, район, долгосрочность. Кому это подходит, решает обычная
арифметика в `users.matches()`.

Поэтому расходы на API зависят от числа объявлений, а не от числа людей —
что один подписчик, что пятьдесят. Обратная сторона: фильтры структурные
(кнопками), а не свободным текстом — свободный текст нельзя сверить без
ещё одного обращения к модели.

| Файл | Что внутри |
|---|---|
| `main.py` | Мониторинг чатов, опрос ss.ge, извлечение фактов, раздача |
| `users.py` | Подписчики, сверка фильтров, сборка regex из кнопок |
| `config.py` | `config.json`, миграция, промпт извлечения |
| `keyboards.py` | Инлайн-меню |
| `commands.py` | Диалог с ботом, одобрение доступа |
| `districts.py` | Канон районов Тбилиси и нормализация написаний |
| `stats.py` | Счётчики воронки и оценка расходов |
| `chats.py` | Резолв чатов, ссылки на сообщения |
| `ssge.py` | Опрос и разбор выдачи ss.ge |

### Два источника, две схемы отсева

| | Telegram | ss.ge |
|---|---|---|
| Как приходит | live-подписка, задержка секунды | опрос по таймеру, по умолчанию раз в 10 мин |
| Дешёвый отсев | regex-предфильтр, собранный из кнопок | цена выше самого щедрого бюджета среди активных |
| Дедуп | по тексту, 24 ч, в памяти | по id объявления, на диске (`ssge_seen.json`) |

Regex-предфильтр к ss.ge не применяется: он про русские сообщения из чата, а
описания на ss.ge грузинские.

## Установка (на вашем VPS)

Нужен Debian/Ubuntu и Python 3.10+.

```bash
git clone git@github.com:boriskobezhikov/klumbabot.git /opt/klumba-bot
bash /opt/klumba-bot/deploy/install.sh
nano /opt/klumba-bot/.env
bash /opt/klumba-bot/deploy/login.sh
systemctl start klumba-bot
```

`install.sh` ставит пакеты, заводит системного пользователя `klumba`, собирает
venv, раскладывает права и регистрирует сервис. Запускать можно повторно —
`.env`, venv и сессию он не трогает.

### Откуда взять значения для .env

- **TG_API_ID / TG_API_HASH** — https://my.telegram.org → «API development tools».
- **NOTIFY_BOT_TOKEN** — @BotFather, `/newbot`.
- **NOTIFY_CHAT_ID** — ваш личный chat id. Он же назначается **владельцем**:
  этот аккаунт всегда активен, одобряет чужие заявки и правит общие настройки.
  Узнать: напишите боту, откройте
  `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, возьмите `"chat":{"id": ...}`.
- **ANTHROPIC_API_KEY** — https://platform.claude.com, с привязанной картой.
- **ANTHROPIC_WORKSPACE_ID** — нужен **только** для ключей, привязанных к
  личности (identity-linked). Такой ключ без него отвечает
  `400 anthropic-workspace-id is required`. Взять id: Settings → Workspaces
  или из адреса `platform.claude.com/workspaces/<этот-id>/…`. Для обычных
  ключей переменную задавать не надо — заголовок тогда не отправляется.

### Первый вход

```bash
bash /opt/klumba-bot/deploy/login.sh
```

Telethon спросит номер и код (код приходит в приложение Telegram, не по SMS).
Разовая операция. **Никому не отправляйте `.session` файлы** — они равносильны
доступу к вашему аккаунту.

## Пользование

### Подписчики

Любой человек пишет боту `/start` → вам приходит заявка с кнопками
«Разрешить / Отклонить». После одобрения он настраивает себе фильтры и получает
уведомления. Отключить можно в любой момент через «👥 Люди».

Пока заявка не одобрена, бот не отвечает ни на что, кроме `/start`.

### Меню

`/menu` открывает кнопки:

| Кнопка | Что делает |
|---|---|
| ⚙️ Мои фильтры | Спальни, комнаты, цена, площадь, районы, источники, пожелания |
| 📊 Что настроено | Сводка; владельцу — ещё и общее состояние сбора |
| ⏸ Пауза | Приостановить уведомления, не теряя настроек |
| 👥 Люди | *(владельцу)* заявки и доступ |
| 🛠 Сбор | *(владельцу)* опрос ss.ge, предфильтр, интервал, страницы |
| 📈 Статистика | *(владельцу)* сколько собрано, сколько ушло в Claude, во что обошлось |

Текстовых команд осталось немного: `/menu`, `/status`, `/stop`, `/help`,
а владельцу ещё `/chats`, `/users`, `/stats`, `/rate`.

### Цена и площадь

У цены две границы. Верхняя — привычный бюджет. Нижняя (по умолчанию не
задана) отсекает то, что дешевле разумного: комнаты, углы и объявления с
ценой-заглушкой. Обе меняются на одном экране: верхний ряд кнопок — нижняя
граница, нижний — верхняя.

Границы не дают друг другу перехлестнуться. Если опустить верхнюю ниже
нижней, нижняя опустится следом — иначе фильтр стал бы пустым и уведомления
просто перестали бы приходить без всякого объяснения.

У площади только нижняя граница: большая квартира по твоей цене помешать не
может.

⚠️ **Объявления без цены или без указанной площади проходят всегда.** Это то
же правило, что и для остальных фильтров: неизвестный факт трактуется в
пользу объявления. На ss.ge площадь есть почти везде, а в чатах её пишут
далеко не всегда — если резать по её отсутствию, потеряется много живого.

Обе границы работают и как дешёвый отсев для ss.ge: если объявление не
проходит по самой мягкой границе среди всех активных подписчиков, оно
отбрасывается до вызова Claude. В статистике это строки «отсеяно по цене» и
«отсеяно по площади».

### Пожелания свободным текстом

Кнопки покрывают измеримое: цену, комнаты, район. Всё остальное — балкон,
животные, этаж, техника — пишется обычным текстом в «📝 Пожелания», и Claude
сверяет с ним объявления.

Это **второй, платный вызов**, поэтому он ленивый: срабатывает только для
объявлений, уже прошедших остальные фильтры этого человека, и только если
пожелания вообще заданы. Кто их не заполнил — не платит ничего.

Проверка намеренно снисходительна: если про требование в объявлении ничего не
сказано, оно считается ненарушенным. Отсекается только явное противоречие —
иначе молчаливые объявления терялись бы пачками. Если проверка не удалась
(сбой API), объявление всё равно доставляется с оговоркой: лучше лишнее
уведомление, чем потерянная квартира.

### Статистика

`/stats` или кнопка «📈 Статистика» показывает воронку в трёх окнах — час,
сутки, за всё время:

```
сообщений в чатах          430     430     5160
прошло предфильтр           52      52      624
получено с ss.ge          4600    4600    55200
из них новых               180     180     2160
отсеяно по цене             41      41      492
отсеяно по площади          12      12      144
карточек догружено         139     139     1668
разборов в Claude          191     191     2292
личных проверок             34      34      408
уведомлений разослано       17      17      204

Claude за сутки: ~$0.35
В месяц по темпу суток: ~$10.39
```

По ней видно, где деньги: `разборов в Claude` — общий счёт, `личных проверок` —
доплата за свободные пожелания. Оценка стоимости приблизительная, считается по
числу вызовов и типичному размеру запроса, а не по фактическим токенам.

`карточек догружено` — это запросы к ss.ge, а не к Claude: они бесплатны, но по
ним видно, доходит ли бот до детальных страниц. Если счётчик стоит на нуле, а
`отсеяно по цене` растёт — значит сайт отдаёт карточки не так, как ожидается,
и Claude судит только по описанию.

Итоги за всё время лежат в `stats.json` и переживают перезапуск; скользящие
окна живут в памяти и после рестарта начинаются заново.

Счётчик **«ОШИБОК Claude»** считается отдельно от разборов. Если он растёт, а
разборы стоят — API не отвечает: сводка покажет текст ошибки, и владельцу
придёт разовое уведомление. Сбор при этом продолжается.

### Почему мне ничего не приходит

Три способа разобраться, по возрастанию усилий:

1. **`/last`** — последние 15 разборов с фактами и вердиктом по каждому
   подписчику: видно, какой именно фильтр отсёк объявление.
2. **`/stats`** — где обрывается воронка. Если «разборов в Claude» есть, а
   «уведомлений» нет — смотри «никому не подошло». Если и его нет, а есть
   «ОШИБОК Claude» — проблема в API.
3. **Самопроверка** — делает по одному пробному запросу к Claude и ss.ge,
   показывает настройки всех подписчиков и считает, сколько объявлений прошло
   бы их фильтры прямо сейчас:

```bash
/opt/klumba-bot/venv/bin/python /opt/klumba-bot/deploy/doctor.py
```

Ничего не меняет и не печатает секреты. Возвращает ненулевой код, если нашла
проблемы.

⚠️ **Частая ловушка со спальнями.** ss.ge проставляет `спален: 1` и
однокомнатным, и двухкомнатным квартирам. Если в фильтре отмечено «2 спальни»,
с этого источника не пройдёт ничего. Для «одной спальни любой планировки»
нужно: спальни **1**, комнаты **1 и 2**.

### Спальни и комнаты — не одно и то же

В грузинских и русских объявлениях комнаты считают вместе с гостиной:

| комнат | реальных спален | средняя площадь |
|---|---|---|
| 1 | 1 | ~37 м² |
| 2 | **1** | ~50 м² |
| 3 | 2 | ~83 м² |

Нужна одна спальня независимо от планировки — отметьте комнаты **1 и 2**.
Claude инструктирован считать спальни по этому же правилу.

### Как из кнопок получается regex

Предфильтр для чатов и параметр `rooms` для ss.ge **выводятся автоматически**
как объединение фильтров всех активных подписчиков: собираем то, что нужно
хоть кому-то, а раздаём уже по личным фильтрам. Поэтому:

- когда человек отмечает «3 комнаты», ss.ge начинает запрашивать и их;
- когда он уходит на паузу, его запросы выпадают из объединения.

Текущий собранный regex видно владельцу в «🛠 Сбор».

## Как работает ss.ge

Бот запрашивает страницу выдачи долгосрочной аренды в Тбилиси,
отсортированную по свежести, и читает JSON, который сайт кладёт в
`__NEXT_DATA__` для собственной отрисовки. Ни headless-браузера, ни парсинга
вёрстки.

Посуточная аренда живёт на отдельном URL и в выдачу не попадает, но Claude
всё равно перепроверяет срок по тексту.

**Список комнат обходится отдельными запросами.** Сайт принимает `rooms=1,2`,
но серверный рендер такой фильтр молча игнорирует и отдаёт всё подряд
(мультивыбор доезжает только клиентским дозапросом, а бот читает серверный
HTML). Одиночное значение фильтруется корректно. Отсюда число запросов —
`значений комнат × pages`: при комнатах `1,2` и `pages=2` это 4 запроса раз в
10 минут, с паузой в секунду между ними.

**Карточка догружается отдельно.** В выдаче поиска нет ни удобств, ни этажа, ни
состояния ремонта — только цена, площадь, спальни и описание. Всё остальное
живёт на странице объявления. Поэтому для каждого объявления, прошедшего по
цене, бот делает ещё один запрос — за детальной карточкой — и берёт оттуда:

- **удобства**: балкон, лифт, мебель, кондиционер, отопление, техника,
  парковка, «можно с животными» и ещё полтора десятка флагов;
- **этаж из скольких**, состояние ремонта, тип дома, число комнат;
- **описание на русском или английском**, если автор его заполнил — Claude
  читает их точнее, чем грузинский.

Карточка берётся в русской локали (`/ru/`), поэтому «Новый ремонт» и
«Новостройка» приходят уже переведёнными, и ссылка в уведомлении открывается
на русском.

Без этого запроса Claude видел только текст описания, а балкон или мебель на
ss.ge обычно не описывают словами — их показывают на фото. Фотографии боту
недоступны, и объявление отсеивалось «потому что не написано».

⚠️ **`false` у флага удобства значит «автор не поставил галочку», а не
«этого нет».** Проверяется в одну строку: у квартиры на 14-м этаже
`water`/`electricity`/`sewage` приходят `false`. Поэтому в промпт уходят
только отмеченные удобства, а про остальные Claude прямо предупреждают, что
сайт молчит.

⚠️ **На несуществующее объявление ss.ge отвечает HTTP 200 с карточкой из одних
`null`, а не 404.** Если это не проверять, объявление получило бы «удобств
отмечено: ни одного» как утверждение сайта. Поэтому `applicationId` в карточке
сверяется с id объявления, и при несовпадении догрузка считается неудачной —
объявление уходит в Claude в том виде, в каком пришло из выдачи, а не с
выдуманными фактами.

**Первый запуск ничего не рассылает.** Бот запоминает текущую выдачу и дальше
уведомляет только о новом. Просмотренные id лежат в `ssge_seen.json` (последние
5000), поэтому перезапуск не приводит к повторной рассылке.

Если ss.ge поменяет структуру страницы, опрос не упадёт молча — ошибка попадёт
в «📊 Что настроено», а мониторинг чатов продолжит работать.

## Эксплуатация

```bash
systemctl status klumba-bot
journalctl -u klumba-bot -f
bash /opt/klumba-bot/deploy/update.sh   # git pull + зависимости + перезапуск
```

Процесс работает под системным пользователем `klumba` без shell, код ему
недоступен на запись, `.env` в режиме `640`, юнит закрыт systemd-песочницей.
Подробности — в `deploy/install.sh` и `klumba-bot.service`.

### config.json

Создаётся автоматически. Общее — чаты, параметры ss.ge, курс; личное — по
подписчикам. Конфиг старого формата мигрирует сам при первом запуске: настройки
владельца (бюджет, комнаты) переезжают в его профиль, чаты и параметры опроса
сохраняются. Путь переопределяется переменной `KLUMBA_CONFIG`.

## Ограничения

- Из чатов ловятся только сообщения, появившиеся пока бот запущен. Пропущенное
  за простой не восстанавливается. С ss.ge проще: всё, что появилось за
  простой, попадёт в следующую выдачу, если не ушло глубже `pages` страниц.
- ss.ge опрашивается по таймеру, поэтому объявление приходит не мгновенно,
  а в пределах интервала.
- Структурные фильтры бесплатны и не зависят от числа людей. Свободные
  пожелания стоят отдельного вызова на человека — но только для объявлений,
  доживших до его фильтров. Текст критериев из однопользовательской версии в
  фильтрации не участвует, он сохранён в `legacy_criteria`.
- Подписчики получают объявления из **ваших** чатов, читаемых вашим личным
  аккаунтом. Одобряя человека, вы открываете ему этот поток.
- Claude может ошибаться в разборе, особенно на грузинском. Это фильтр для
  экономии времени, а не гарантия не пропустить ничего.
